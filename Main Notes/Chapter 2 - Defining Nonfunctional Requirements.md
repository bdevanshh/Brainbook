# Chapter 2 - Defining Nonfunctional Requirements

### Functional Requirements
The list of functionalities that the application **must** offer are called Functional Requirements.
e.g., screens and buttons, purpose of each operation

### Nonfunctional Requirements
The requirements which are obvious and not explicitly defined are called Non-Functional Requirements.
e.g., reliability, performance, security

### Materialization
The process of precomputing and updating the result of a query is called Materialization
e.g., precomputing the home timeline of a social network site when a followee make a post.

### Response Time
The elapsed time from the moment when a user makes a request until they receive the requested answer. It is measured in seconds.

### Throughput
The number of requests per second, or the data volume per second, that the system is processing. It is measured in something per second.

### Latency
Time during which a request is not being actively processed is called Latency.
e.g., Network latency

### Jitter
Variations in network delay

### Tail Latencies
High response-time percentiles.
e.g., P95, P95, P999 

### Reliability
Continuing to work correctly, even when things go wrong.

### Faults
A fault occurs when a particular part of the system stop working correctly.
e.g., single hard drive failure

### Failure
A failure occurs when the system as a whole stops providing the required service to the user.
e.g., all the hard drive fails

### Fault Tolerance
A system is called Fault Tolerance if it continues providing the required service to users in spite of certain faults occurring.

### Single Point of Failure
If a system cannot tolerate a certain part becoming faulty, then that part can be called a single point of failure.

### Scalability
Scalability is the term used to describe the systems's ability to cope with increased load.

### Vertical Scaling
The approach for adding more CPUs, RAM and disk space to handle more load is called Vertical Scaling or **Scaling Up**.

### Horizontal Scaling
A distributed system with multiple nodes, each of which has its own CPUs, RAM and disk is called Horizontal Scaling or **Scaling Out**. 

### Operability
Operability of a system determines how much easy it is for the organization to keep the system running smoothly.

### Simplicity
Simplicity make it easy for new engineers to understand the system, by implementing it using well-understood, consistent patterns and structures and avoiding unnecessary complexity.

### Evolvability
Evolvability make it easy for engineers to make changes to the system in the future, adapting it and extending it for unanticipated use cases as requirements change.
